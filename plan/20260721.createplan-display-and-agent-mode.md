# createPlan 展示优化 + 强制 agent mode

> **文档定位**：**活 spec**（会随实施反复更新）——「关键决策与未决项」表是唯一真相源，正文引用它、不复述它。

## 0. 一页纸（骨架先行）

- **一句话**：每次用户发消息钉死 `mode: "agent"`，避免会话 sticky 在 plan；把 `createPlan` 从 JSON 工具兜底改成默认展开的 markdown 计划正文。
- **承重决策**：
  1. **强制 agent mode** —— 每次 `agent.send` 显式带 `mode: "agent"`，因为 omit 会 sticky 当前 mode，而 local SDK 会静默批准 SwitchMode（详见 〈决策·force-agent-mode〉）。
  2. **扩 toolFormat，不新建计划卡** —— 展示痛点在格式化，沿用现有工具块即可（详见 〈决策·extend-tool-format〉）。
  3. **plan 用 markdown、默认展开** —— createPlan 常是本轮主产出，JSON 墙不可读（详见 〈决策·createplan-md〉、〈决策·createplan-default-open〉）。
  4. **不豁免整包、不做 Build 按钮** —— 末项本就在「中间过程」外；续聊一句 + 强制 agent 即可开干（详见 〈决策·no-collapse-carveout〉、〈决策·no-build-button〉）。
- **验收总目标**：所有用户发送的 `send` 都带 `mode: "agent"`；历史与直播里 createPlan 默认展开且正文为 markdown；其它工具/整包行为不变；畸形 payload 不白屏。

## 1. 需求背景

### 1.1 原始需求
> 优化 Create Plan 这个工具调用的展示，然后在每次用户发送消息的时候都带上 Mode 等于 Agent 这个参数。

补充确认：`args.plan` 用 markdown 渲染；createPlan 默认展开；不特殊豁免整包折叠（依赖末项在外）；不做「开始执行」按钮。

### 1.2 背景与动机
模型偶发进入 Plan 流程后只吐 `createPlan` 就结束本轮。这是 Plan Mode 闸门语义，不是 SDK 卡死。本仓库未传 `mode`，且 local SDK 对 `SwitchMode` 自动批准、对 AskQuestion 自动拒绝，导致用户只看见 createPlan JSON，且后续发送若仍 omit `mode` 可能 sticky 在 plan。

### 1.3 目标与验收标准
- 新建与续聊路径的每一次用户消息 `send` 都含 `mode: "agent"`。
- createPlan：折叠条为人话摘要；详情为 `args.plan` 的 markdown；默认展开。
- 整包「中间过程」语义不变；无 Build 按钮。
- `plan` 缺失/非 string、或 `marked` 未加载时退回安全兜底，不白屏。

### 1.4 约束与前提
- 不改 SSE / runHub / history 协议；不动 agent 主循环（详见 〈决策·frontend-plus-send-only〉）。
- 展示扩展点对齐已有 `toolFormat.js`（详见 〈决策·extend-tool-format〉）。
- 无法从应用层禁止当轮内先 SwitchMode 再 createPlan；靠每轮 send 钉 agent 纠正 sticky（详见 〈决策·force-agent-mode〉）。

## 2. 现状分析

### 2.1 相关代码/系统现状
- **发送**：`agentService.sendMessage`——新建 `agent.send(text)`，续聊 `agent.send(text, { model })`，均无 `mode`。`Agent.create` / `resume` 亦未设 mode（SDK 默认首次为 agent）。
- **展示**：历史 `appendStepsWithCollapse` → `renderConversationStep` → `appendToolBlock`；直播 SSE `tool_call` → `updateToolBlock`。摘要/详情在 `toolFormat.js`（目前优先 shell/read/grep/edit）。
- **整包**：除最后一项外收入「中间过程 · N 项」。createPlan 作为末项时留在外面。
- **markdown**：页面 CDN `marked`；`render.js` 的 `renderMarkdown` 已用于 assistant / 文件预览。

### 2.2 现状与目标的差距

| 目标 | 现状 | Gap |
|------|------|-----|
| 每轮 agent mode | send 不传 mode | 两处 send 加 `mode: "agent"` |
| createPlan 可读 | JSON 兜底 | toolFormat 增加 createPlan 分支 |
| 默认展开 | 一律折叠 | append/update 对 createPlan 打开 detail |
| 整包 / Build | 末项在外；无按钮 | 无 gap（明确不做） |

### 2.3 影响范围
- **必改**：`src/agentService.ts`、`public/toolFormat.js`、`public/render.js`；按需 `public/style.css`。
- **不动**：`runHub`、SSE、`history.ts`、composer 发消息协议、AskQuestion / SwitchMode 交互。
- **回归面**：新建/续聊 send；历史重渲与直播 running→completed；其它工具默认折叠；整包折叠；未知工具 JSON 兜底。

## 3. 方案设计

### 方案 A：钉 mode + 扩 toolFormat（选定）
- **思路**：每次用户消息的 `send` 显式 `mode: "agent"`；createPlan 走 toolFormat 人话摘要 + markdown 详情，并默认展开。
- **改动范围**：`agentService.ts`、`toolFormat.js`、`render.js`、必要时 `style.css`。
- **优点**：改动小；与既有工具渲染扩展点一致；满足全部已确认验收。
- **缺点**：仍是工具条 UI，不是独立「计划文档卡」。
- **工作量**：S

### 方案 B：A + 专用计划卡（未选）
- **思路**：createPlan 不用 `.block-tool`，另做类 assistant 的计划卡。
- **未选原因**：需求未要求；历史/直播双路径成本高，且与工具身份语义分叉。

### 最终选定
**方案 A**。

### 执行步骤
1. **钉 mode** —— 新建与续聊两处 `agent.send` 都传 `mode: "agent"`；续聊保留现有 `model` 覆盖。为什么：omit 会 sticky，必须每轮显式纠正（详见 〈决策·force-agent-mode〉）。
2. **toolFormat 扩 createPlan** —— `normalizeName === "createplan"`：摘要取 plan 首行截断；详情渲染 `args.plan` 为 HTML。为什么：避免 `toolFormat` ↔ `render` 循环依赖，markdown 用全局 `marked`（或与 `renderMarkdown` 同逻辑的叶子实现），失败则 escape+`<br>` / JSON（详见 〈决策·createplan-md〉、〈决策·md-no-cycle〉）。
3. **默认展开** —— `appendToolBlock` / `updateToolBlockEl`：createPlan 且非 running 时给 `.tool-detail` 加 `open`，toggle 文案同步。为什么：计划常是本轮主产出（详见 〈决策·createplan-default-open〉）。
4. **CSS 按需** —— 详情容器可挂 `.msg-text` 或轻量 `.tool-plan-md`，与 assistant markdown 观感接近；不上新高亮库。
5. **typecheck** —— 后端选项变更后跑 `npm run typecheck`。

### 压力测试

| 压力维度 | 具体场景 | 方案表现 | 是否需要防御性设计 |
|----------|---------|----------|------------------|
| 故障容错 | `args.plan` 缺失/非 string | 退回 JSON 详情 | 是（已纳入 toolFormat 兜底） |
| 故障容错 | `marked` 未加载 | escape + `<br>` | 是（与 renderMarkdown 同） |
| 残余接受 | createPlan 后还有 assistant 短文本 | createPlan 进整包 | 否（〈决策·no-collapse-carveout〉） |
| 外部契约 | SDK 静默批准 SwitchMode | 当轮仍可能 createPlan；下轮 send 钉回 agent | 展示优化覆盖可见结果；不尝试拦截 SwitchMode |
