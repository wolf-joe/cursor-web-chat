# 未提交改动 Diff 查看（宽幅 Overlay）

> **文档定位**：**活 spec**（会随实施反复更新）。
> 「关键决策与未决项」表是唯一真相源；正文引用它、不复述它。

## 0. 一页纸（骨架先行）

- **一句话**：给标题栏已有的 `diff N` 入口接上同页宽幅 Overlay，只读查看当前文件夹未提交的文件列表与 patch 内容，方便边聊边核对 agent 改了什么。
- **承重决策**（3~5 条）：
  1. **同页宽幅 Overlay** —— 不新开路由/tab，盖住主对话区近全宽展示，因为动机是边聊边核对且现前端无路由（详见 §3 / 〈决策·overlay-shell〉）。
  2. **按 cwd、不绑会话** —— diff 是文件夹工作区属性，API 与 UI 只传当前 cwd（详见 〈决策·cwd-scoped〉）。
  3. **只读未提交** —— MVP 只看 staged / unstaged / untracked，不做 commit/stage/discard（详见 〈决策·readonly-uncommitted〉）。
  4. **硬截断** —— 最多 100 个文件；二进制与超过 2000 行的内容不展示正文，只标跳过原因（详见 〈决策·truncation〉）。
  5. **盖 UI、不断 SSE** —— 打开 Overlay 不得 `detachStream`，关闭后聊天累积状态仍在（详见 〈决策·keep-stream〉）。
- **验收总目标**：有 dirty 时点 `diff N` 能打开宽 Overlay，看到文件列表与文本 diff；截断/错误有明确提示；打开期间对话流式不停；Esc/关闭可退回。

> 读者读完这一节，应已掌握「做什么、凭什么这么定、怎么算成功」。后面是证据与落地步骤。

## 1. 需求背景

### 1.1 原始需求

> 在现有的文件夹旁边，展示 diff 数量的按钮的基础上，增加一个 diff 页的展示，能够看到当前有哪些文件有改动，并且改动的内容是什么。推荐一下展示的方案，比如说新页面还是当前页面，又或者是说，在新的 tab 页，或者是移动当前 tab 页，然后移动到新页面。

后续确认：边聊边核对 Agent 改了什么；不和当前会话强绑定；MVP 只看未提交改动；只读；可接受新增 API；最多展示 100 个 diff；二进制和超过 2000 行的内容不展示；展示形态选定同页宽幅 Overlay（方案 A）。

### 1.2 背景与动机

Agent 在 local 运行时直接改磁盘文件。用户需要在对话过程中快速核对「当前文件夹工作区被改了什么」，而不是离开聊天去终端跑 `git diff`。标题栏 `diff N` 已是入口，缺的是文件列表与内容展示。

### 1.3 目标与验收标准

- 点 `diff N` 打开近全宽 Overlay：左文件列表、右 unified diff（或跳过说明）。
- 数据范围与截断按 〈决策·readonly-uncommitted〉〈决策·truncation〉。
- 打开期间 SSE 不断（〈决策·keep-stream〉）；Esc / 关闭按钮退出。
- 非 git / 不在白名单 / git 失败：明确错误或安全降级，不空白卡死。

### 1.4 约束与前提

- 前端仍是无构建单页、无客户端路由；新增能力应落在现有 `public/` + Express API 模式内。
- git 查询仅允许 `config.json` 文件夹白名单中的 cwd（与现有 `/api/git-status` 一致，详见 〈决策·cwd-allowlist〉）。
- 会随实施微调的截断阈值、API 字段名等收口在 §5，正文不展开多份。

## 2. 现状分析

### 2.1 相关代码/系统现状

- **入口**：`public/gitStatus.js` 在切换会话、run 结束、窗口 focus 时刷新；有 dirty 显示 `diff N`；点击目前 `console.info` 占位（`未决·git-diff-page`）。
- **后端**：`src/gitStatus.ts` + `GET /api/git-status` 返回 `repo/dirty/branch/counts`，用 `git status --porcelain`，不返回文件列表或 patch。
- **前端壳**：单一 `index.html`；主区为聊天；已有居中小 modal（模型参数，约 380px），无抽屉/路由。`express.static` 托管 `public/`。

### 2.3 现状与目标的差距

| 目标 | 现状 | Gap |
|------|------|-----|
| 看哪些文件改了、改了什么 | 只有计数按钮 | 缺列表 + patch API 与 Overlay UI |
| 边聊边看 | 单页聊天 | 需同页 Overlay，且不断开 stream |
| 截断与跳过规则 | 无 | 需后端强制执行 〈决策·truncation〉 |

### 2.4 影响范围

- **会改**：`src/gitStatus.ts`（或并列 `gitDiff.ts`）、`src/server.ts`、`public/gitStatus.js`、新建 `public/gitDiff.js`（名可调）、`public/index.html`、`public/style.css`、`public/api.js` / `dom.js`；切换会话时关闭或按新 cwd 重拉 Overlay。
- **基本不动**：`agentService` / `runHub` / `history` / 侧边栏会话模型 / 标题服务。

## 3. 方案设计

### 方案 A：宽幅全屏 Overlay（选定）

- **思路**：点击 `diff N` → 打开盖住主对话区的近全宽 Overlay（左右可留窄边距）。顶栏：文件夹名 / 分支、刷新、关闭。主体：左侧改动文件列表，右侧选中文件的 unified diff。Esc 或关闭返回对话。
- **改动范围**：后端新增（或扩展）按 cwd 的 diff API；前端 Overlay DOM + 渲染模块；接线现有 dirty 按钮。
- **优点**：阅读宽度最大；无路由；与「边聊边核对」动机一致；实现可类比现有 modal 放大。
- **缺点/风险**：打开时看不见对话气泡（stream 仍在后台推进）；大仓库需硬截断。
- **工作量**：M

### 方案 B：右侧宽抽屉（未选）

露出一截聊天，但 diff 列宽更差，小屏几乎全屏，布局成本更高。

### 方案 C：主区视图切换（未选）

宽度好，但完全看不到对话，且更容易误伤 stream 订阅生命周期。

### 方案对比

| 维度 | A 宽 Overlay | B 右抽屉 | C 主区切换 |
|------|--------------|----------|------------|
| diff 阅读宽度 | 最好 | 中–好 | 最好 |
| 边看边瞥对话 | 差 | 最好 | 差 |
| 与现有 UI | 扩 modal | 新模式 | 中 |
| 回归风险 | 低 | 中 | 中（易碰 stream） |

### 最终选定

**方案 A**，因为用户明确选定同页内嵌且要求宽度利于看 diff；在无路由单页下实现成本与动机匹配最好。

### 执行步骤

原则：**先有后端契约与截断，再画 UI；接线时明确不碰 stream。**

1. **后端 diff API** —— 白名单 cwd 校验与 status 同源（〈决策·cwd-allowlist〉）；返回分支、文件条目（path + staged/unstaged/untracked 等状态）、每文件 patch 或 `skipped`+原因；在服务端执行 〈决策·truncation〉，避免前端自己再截一半。
2. **Overlay 壳** —— `index.html` 增加近全宽面板（不要复用 380px 参数 modal 宽度）；顶栏标题/刷新/关闭；Esc 关闭（〈决策·overlay-shell〉）。
3. **列表 + unified diff 渲染** —— 左点选右展示；等宽字体 + 红/绿行即可；skipped 显示原因。不强制引入第三方 diff 库。
4. **接上 `gitDirtyBtn`** —— 替换 `console.info` 占位；打开时拉取当前 `state.currentCwd`。
5. **会话切换与过期请求** —— 切换 cwd 时关闭 Overlay 或按新 cwd 重拉；请求序号/cwd 校验丢弃过期响应（与 `gitStatus.js` 同套路）。
6. **回归确认** —— 打开/关闭路径上不调用 `detachStream`（〈决策·keep-stream〉）。

### 压力测试

| 压力维度 | 具体场景 | 方案表现 | 是否需要防御性设计 |
|----------|---------|----------|------------------|
| 故障容错 | git 超时 / 非 repo / cwd 不在白名单 | 明确 error，面板可展示错误文案 | 是：API 与 UI 都要有失败态 |
| 规模压力 | 上千文件或超大 patch | 不加硬限制会拖垮 Node/浏览器 | 是：〈决策·truncation〉必须服务端强制 |
| 操作风险 | Overlay 打开时 agent 仍在改文件 | 内容可能过期 | 是：手动刷新；不做自动轮询（避免列表抖动） |
| 并发过期 | 切换文件夹后旧请求返回 | 可能刷错 cwd 的 diff | 是：seq/cwd 校验 |
| 与对话并存 | 打开 Overlay 时 SSE 仍在推 | 若误 `detachStream` 会丢直播 | 是：〈决策·keep-stream〉 |

### 5.2 未决项

| 名字 | 问题 | 类型 | 责任方 | 状态 |
|------|------|------|--------|------|
| api-shape | 新建 `/api/git-diff` 还是扩展 `/api/git-status`；响应字段最终命名 | 边界 | 实施时定，文档回写 | ✅ 已定：新建 `GET /api/git-diff?cwd=`；响应 `{ repo, branch, truncated, files:[{ path, label, statuses, patch, skipped }] }`；status 保持轻量供标题栏轮询 |
| untracked-presentation | 未跟踪文件展示全文还是「新文件」头 + 全文；与 diff 同源字段如何标注 | 边界 | 实施时定 | ✅ 已定：`git diff --no-index -- /dev/null PATH`（带 new file 头的 unified diff）；`statuses:["untracked"]`、列表 `label:"A"`（与新增一致，不用 `?`） |
| empty-while-open | 打开 Overlay 后工作区被清空（不再 dirty）：关闭按钮旁是否自动关，还是显示空态 | 边界 | 用户可随后定 | ✅ 已定：显示空态，不自动关闭（手动关 / Esc） |
| layout-ratio | 左列表/右 diff 默认宽度比例（如 28%/72%） | 遗漏 | 实施时按可读性微调 | ✅ 已定：左列表约 28%（min 180 / max 320px），右侧占余下 |

> **外部契约**：本方案依赖本机 `git` CLI。已验证命令样例：
> - `git status --porcelain` —— 跟踪文件 XY；未跟踪目录只给 `?? dir/`，故未跟踪文件另用 `git ls-files --others --exclude-standard`
> - `git diff -- PATH` / `git diff --cached -- PATH` —— 有差异时 exit 1，stdout 仍为 unified diff
> - `git diff --no-index -- /dev/null PATH` —— 未跟踪「新文件」diff，有差异时 exit 1
> - `git diff --numstat`（及 `--cached` / `--no-index`）—— 二进制为 `-	-	path`；行数用 added+deleted
> 状态：✅ 实施时已用临时 dirty 仓库验证。
