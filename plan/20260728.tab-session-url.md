# 多 Tab 会话：URL 驱动恢复

> **文档定位**：**活 spec**（会随实施反复更新）。「关键决策与未决项」表是唯一真相源，正文引用它、不复述。

## 0. 一页纸（骨架先行）

- **一句话**：用地址栏 query 代替全局 `localStorage:lastSession`，让每个 tab 的「当前 cwd/agent」随 URL 走，从而多 tab 并行、刷新可恢复、互不抢写。
- **承重决策**：
  1. **URL 为唯一恢复源** —— 弃用 `lastSession`；无参根路径即空白落地，因为关 tab / 新开首页不需要继承「全局上次」（详见 〈决策·drop-lastSession〉）。
  2. **参数形态** —— `cwd` 必选才有会话上下文，`agent` 可选；未发消息的新建只带 `cwd`（详见 〈决策·url-shape〉）。
  3. **全程 `replaceState`** —— 地址栏同步当前态，但不把会话切换推进历史栈，避免后退在会话间乱跳、也免去 `popstate`（详见 〈决策·replace-only〉）。
  4. **非法/过期降级** —— cwd 不在白名单 → 空白并清 query；agent 失效 → 该 cwd 新建并 URL 仅留 `cwd`（详见 〈决策·url-degrade〉）。
  5. **name 不进 URL** —— 标题仍靠内存与侧边栏列表校正，避免把展示文案打进可分享地址（详见 〈决策·name-memory-only〉）。
- **验收总目标**：多 tab 各开不同会话并刷新互不串；复制 tab 继承同一 URL 会话；根路径空白；首条消息落地后刷新仍回到该 agent；切换会话不增加历史条目。

## 1. 需求背景

### 1.1 原始需求
> 「目前最新的会话数据好像是存在 local storage 的……可能会出现多个 tab 同时在跟不同的会话聊天……希望让前端支持各 tab 页并行会话，并且刷新后依然保留。」
> 后续确认：「url 参数驱动恢复」；关 tab 再开 / 打开首页可接受新建；复制 tab 继承同一会话。

### 1.2 背景与动机
同源下 `localStorage` 全局一把钥匙，任一 tab 的 `persistSession` 覆盖「上次会话」。并行聊天（内存 state + SSE）本身已可用，冲突只在刷新恢复。需要把「当前打开谁」从进程全局书签改成 **per-document（随 URL）** 的状态。

### 1.3 目标与验收标准
见 §0 验收总目标；清单见 §4.2。

### 1.4 约束与前提
- 只改前端会话书签/恢复；对话真源仍是服务端 SQLite；不改 agent 主循环协议。
- 不要求 tab 间实时同步选中态、不做跨设备同步。
- 默认不保留对 `lastSession` 的兼容回退（详见 〈决策·drop-lastSession〉）。
- 历史栈策略固定为 replace-only（详见 〈决策·replace-only〉）；非法 URL 降级见 〈决策·url-degrade〉。

## 2. 现状分析

### 2.1 相关代码现状
- `state.js`：`persistSession` / `loadPersistedSession` 读写 `cursor-web-chat:lastSession`（`cwd` / `agentId` / `name`）。
- `app.js`：`loadFolders().then(restoreSession)`；`startNewConversation` / `openConversation` 末尾 `persistSession`。
- `composer.js`：新会话首条响应拿到 `agentId` 后 `persistSession`。
- `sidebar.js` / `stream.js`：翻页校正名、标题事件等也会为书签再 persist（主要为缓存 `name`）。
- 无 URL query 读写、无 `history` / `popstate` 路由。

### 2.2 现状与目标的差距
| 目标 | 现状 | gap |
|------|------|-----|
| 每 tab 刷新回自己的会话 | 读全局 lastSession | 恢复源改为 URL |
| 根路径 / 关 tab 再开 → 空白 | 仍按 lastSession 恢复 | 去掉全局书签 |
| 复制 tab 继承会话 | URL 无参，靠碰巧同一 lastSession | query 复制即继承 |
| 并行聊天不串 | 内存已独立 | 无需改直播协议 |

### 2.3 影响范围
- **模块**：`public/state.js`、`public/app.js`、`public/composer.js`；清理 `sidebar.js` / `stream.js` 上仅为 lastSession name 服务的 persist。
- **场景**：启动恢复、侧边栏开/新建、首条落地、删当前会话、打开失败。
- **后端**：一般不动（静态页 + query 由浏览器处理）。

## 3. 方案设计

### 方案 A：URL + 全程 `replaceState`（选定）
- **思路**：用 `?cwd=&agent=` 表达当前会话；所有「当前会话变化」走单一 `syncSessionUrl()` → `history.replaceState`；启动只读 URL restore。
- **改动范围**：前端 session 持久化与启动恢复（上表模块）。
- **优点**：多 tab / 复制 / 刷新自然正确；无 `popstate`；历史不被会话切换污染。
- **缺点**：浏览器后退不能回到上一会话（靠侧边栏即可）。
- **工作量**：S

### 方案 B / C（未选）
- B：切换会话 `pushState` + `popstate` —— 可后退，但须严格区分 push/replace，边界多。
- C：显式切换 push、语义补丁 replace —— 比 B 干净，仍要 `popstate` 与已删 agent 后退降级。
- 未选原因：自用单页、侧边栏已是主导航；A 满足并行与刷新，实现与回归成本最低。

### 最终选定
**方案 A**。

### 执行步骤
原则：**先落单一读写入口，再替换调用点，最后接启动恢复与降级**——避免一半写 localStorage、一半写 URL。

1. **读写封装** —— 在 `state.js`（或极小模块）实现 parse query / `syncSessionUrl()`；删除 lastSession 读写，启动时可 `removeItem` 清旧键（因为旧键只会误导排障，详见 〈决策·drop-lastSession〉）。
2. **写路径对齐** —— `startNewConversation` / `openConversation` / 首条 `agentId` 落地 / 删除当前后的新建：一律 sync URL；仅校正展示名的路径不再为「书签」写入（详见 〈决策·name-memory-only〉）。
3. **启动恢复** —— `restoreFromUrl`：无参→空白；cwd 非法→空白并清 query；仅 cwd→新建；cwd+agent→`openConversation`（列表未加载到也可最小 agentInfo 打开，与现逻辑同）。
4. **打开失败降级** —— conversation 明确失败（会话不存在等）→ 该 cwd 新建 + URL 仅 `cwd`（详见 〈决策·url-degrade〉）。

### 压力测试（残余风险）

| 压力维度 | 场景 | 方案表现 | 是否需要防御性设计 |
|----------|------|----------|------------------|
| 故障容错 | 非法 cwd / 失效 agent | 空白或该 cwd 新建 | 是——降级后 **replace 改写 URL**，避免刷新反复失败（〈决策·url-degrade〉） |
| 竞态 | 首条落地前刷新 | 停在仅 cwd 新建 | 可接受；落地后必须立刻 sync `agent` |
| 规模 | cwd 长路径 | 地址栏很长 | 可接受（自用）；必须 `encodeURIComponent` |
| 演进 | 日后要可后退 | 可在 sync 入口上扩 push/popstate | 当前不做 |

## 4. 实施计划

### 4.1 子任务拆解
| # | 任务 | 涉及文件/模块 | 验收标准 | 优先级 |
|---|------|---------------|----------|--------|
| 1 | URL parse/sync + 移除 lastSession | `public/state.js` | 符合 〈决策·url-shape〉〈决策·replace-only〉〈决策·drop-lastSession〉 | 必须 |
| 2 | 启动 restoreFromUrl + 降级 | `public/app.js` | 符合 〈决策·url-degrade〉；无参空白 | 必须 |
| 3 | 调用点改 sync；首条落地写 agent | `app.js` / `composer.js` 等 | 新建仅 cwd；落地后带 agent | 必须 |
| 4 | open 失败 → 新建 + sync | `public/app.js` | 〈决策·url-degrade〉 | 必须 |
| 5 | 去掉仅服务 lastSession name 的 persist | `sidebar.js` / `stream.js` | 〈决策·name-memory-only〉 | 应该 |

### 4.2 测试要点
- [ ] Tab A/B 不同 `cwd`/`agent`，各自刷新不串
- [ ] 复制 tab → 同一会话
- [ ] 无参 `/` → 空白，不自动恢复
- [ ] 仅 `?cwd=` → 该文件夹新建会话
- [ ] 首条消息后 URL 出现 `agent=`，再刷新仍是该会话
- [ ] 切换会话 / 新建：地址栏变，历史不增加会话条目
- [ ] cwd 不在列表 → 空白且 query 被清
- [ ] agent 已删或打开失败 → 该 cwd 新建，URL 仅 `cwd`
- [ ] 不再读写 `cursor-web-chat:lastSession`
- [ ] 发送 / SSE 直播 / 侧边栏开会话回归正常
