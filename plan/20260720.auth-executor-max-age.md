# LocalExecutor 按 cwd 主动限龄，避免长驻 accessToken 中毒

> **文档定位**：**活 spec**（会随实施反复更新）。
> 「关键决策与未决项」表是唯一真相源；正文引用它、不复述它。

## 0. 一页纸（骨架先行）

- **一句话**：SDK 按 cwd 复用的 `LocalExecutor` 会把 `exchange_user_api_key` 得到的 accessToken 缓存在闭包里，且业务层 `AUTH_TOKEN_EXPIRED` / `NOT_LOGGED_IN` 不会触发重换票；进程内同文件夹会话会连坐。对本仓库 agent 缓存按 cwd 做**租约限龄**，到期主动 `asyncDispose`，逼 SDK 丢掉 executor。
- **承重决策**：
  1. **P2 主动限龄，不被动兜底** —— 不在 auth 失败后再 flush/重试；恢复靠限龄后的冷 create/resume（详见 〈决策·no-auth-fallback〉）。
  2. **年龄按 cwd 计，不按 agent** —— 同 cwd 共享一个 LocalExecutor，`firstLeaseAt` 必须 cwd 级（详见 〈决策·cwd-lease-age〉）。
  3. **默认 45min，env 可覆盖** —— `AGENT_EXECUTOR_MAX_AGE_MS` 默认 `2700000`（详见 〈决策·max-age-45m〉）。
  4. **租约年龄仅超龄打 warn** —— 健康 send 不打 age info；超龄 flush 仍带 `ageMs`（详见 〈决策·lease-age-log〉；2026-07-23 由「每次 send 打」翻盘，见 `docs/proposals/20260723.log-density.md`）。
  5. **dispose 用 `asyncDispose`** —— `close()` 不 await release，refs 可能下不完（详见 〈决策·async-dispose〉）。
- **验收总目标**：同 cwd 连续使用超过限龄后，下一次发消息会先清空闲句柄并重置 `firstLeaseAt`；超龄路径日志可见 `ageMs`；不引入 auth 失败自动重试；`typecheck` 通过。

## 1. 需求背景

### 1.1 原始需求

> Web 应用跑一段时间后发消息立刻报错 “Authentication error If you are logged in, try logging out and back in.”；新建会话同错；重启或换文件夹又好。怀疑 patch 或 SDK 用法。要求根因排查后出方案；选定「主动丢弃 executor、不等 auth 失败」；P2 + 不兜底；开启对话时打日志打印距首次连接多久；限龄 24 小时。

### 1.2 背景与动机

单进程多文件夹托管；agent 句柄缓存会长时间握住 SDK executor lease。accessToken 过期后错误以流内 `ERROR` 出现，SDK 不重换票，同 cwd 全部会话连坐。需要在业务侧主动打断长租约。

### 1.3 目标与验收标准

- 超龄时日志含该 cwd 的 `ageMs` / `maxAgeMs`（健康路径不打租约 info，见 〈决策·lease-age-log〉）。
- `ageMs > AGENT_EXECUTOR_MAX_AGE_MS` 时：dispose 该 cwd 下所有**非 busy** 缓存 agent，再走正常 create/resume/send；该 cwd 的 `firstLeaseAt` 在租约清光后重置。
- **不**根据 auth 文案自动 flush 或重试。
- 不改 `@cursor/sdk` patch；`npm run typecheck` 通过。

### 1.4 约束与前提

- 公开 API 无按 cwd 清 executor 的入口；只能通过释放 agent lease 让 SDK `Ct` refs→0 后 dispose（详见 〈决策·async-dispose〉）。
- 限龄与现有 `AGENT_CACHE_MAX` / `AGENT_CACHE_IDLE_TTL_MS` 正交：后者管内存，前者管 token 寿命窗口（详见 〈决策·max-age-45m〉）。
- 不被动兜底（详见 〈决策·no-auth-fallback〉）。

## 2. 现状分析

### 2.1 相关代码/系统现状

- **`agentService`**：`Map<agentId, CacheEntry>` 缓存活句柄；`create`/`resume` 传 `apiKey` + `local.cwd`；淘汰只 `close()`，未按 cwd 记租约起点。
- **SDK `@cursor/sdk@1.0.23`**：`acquireLocalExecutor` 用 hash(`workingDirectory`,`apiKeyHash`,`settingSources`,…) 做进程内 `Ct` 缓存；`KU`/`Bu` 闭包缓存 accessToken，仅 Connect `Unauthenticated` 时重换；`AUTH_TOKEN_EXPIRED` 等归 `ActionRequired(login)`，不走重换。
- **落盘证据**：`runs.error_code` 即为该 Authentication 文案；同进程他 cwd 仍可 `FINISHED`；失败事件序列为 `RUNNING` → `ERROR`（非传输层 Unauthenticated 重试路径）。

### 2.2 问题定位

- **类型**：上游 SDK 鉴权/租约生命周期缺口，本仓库长缓存放大。
- **根因**：cwd 级 LocalExecutor + 不刷新的 accessToken；业务层 auth 错误不触发重换票。
- **已排除**：API key 整本失效；现有 stall/cwd patch（不碰鉴权）。

### 2.3 现状与目标的差距

| 目标 | 现状 |
|------|------|
| executor 不会无限长住 | 同 cwd 有缓存 agent 时 lease 可跨很多小时 |
| 可观测「挂了多久才 auth」 | 无 `firstLeaseAt` / `ageMs` 日志 |
| 限龄后自动换新 executor | 只能靠重启或碰巧换 cwd / 缓存清空 |

### 2.4 影响范围

- **会改**：`src/agentService.ts`（为主）；可选 `deploy/supervisor.ini` 增加 env 说明；`CLAUDE.md` / `AGENTS.md` 若写缓存 env 则补一行（实施时按需，非必须）。
- **不改**：`patches/`、前端、runHub 鉴权重试逻辑（明确不做）。

## 3. 方案设计

### 选定：P2 按 cwd 租约限龄 + 超龄才打 age 日志（不兜底）

- **思路**：
  1. `CacheEntry` 增加 `cwd`；另维护 `cwd → firstLeaseAt`（该 cwd 仍有任一缓存句柄时保留）。
  2. `admitToCache`：写入 `cwd`；若该 cwd 尚无 `firstLeaseAt` 则记 `Date.now()`。
  3. 淘汰/`asyncDispose` 后若该 cwd 已无缓存条目，删除 `firstLeaseAt`。
  4. `sendMessage` 开头：读 `firstLeaseAt`；若超 〈决策·max-age-45m〉，对该 cwd 非 busy 条目逐个 `await agent[Symbol.asyncDispose]()` 并移出 `agentCache`，busy 则 warn 跳过，并打 〈决策·lease-age-log〉 超龄 warn（含 `ageMs`）；健康路径不打 info。然后再 `create`/`resolveAgent`/`send`。
- **伪代码**（示意）：

```text
sendMessage(agentId?, cwd, text, model):
  first = cwdFirstLeaseAt.get(cwd)
  ageMs = first ? now - first : 0
  if first && ageMs > MAX_AGE:
    log.warn("executor 租约超龄,开始 flush…", { cwd, ageMs, … })
    for each idle entry with entry.cwd == cwd:
      await entry.agent[Symbol.asyncDispose]()
      agentCache.delete(...)
    // 若 cwd 下已无条目 → delete cwdFirstLeaseAt
  // 既有 create / resolve / send 逻辑
```

- **未选**：auth 失败再 flush+重试（用户明确不要兜底）；每轮 run 结束都 dispose（冷启动过重）；只缩短 idle TTL（活跃连聊续命时仍可能中毒）；patch SDK 重换票（升级脆、与现有 patch 叠成本高）。

### 压力测试（残余风险）

| 压力维度 | 具体场景 | 方案表现 | 是否需要防御性设计 |
|----------|---------|----------|------------------|
| 故障容错 | 同 cwd 另有 busy agent，限龄无法把 refs 打到 0 | executor 可能继续存活至 busy 结束；打 warn | 是：warn 日志即可；不杀 busy、不兜底（〈决策·no-auth-fallback〉） |
| 规模压力 | 限龄触发时一次 dispose 多个空闲 agent | 最多 `AGENT_CACHE_MAX` 次；可接受 | 否 |
| 观测 | 45min 内仍出现 auth | 超龄 flush warn 仍带 `ageMs`；健康路径不再每 send 打 age（2026-07-23 翻盘） | 是：已纳入 〈决策·lease-age-log〉；细对照另开需求 |

## 4. 实施计划

### 4.1 子任务拆解

| # | 任务 | 涉及文件/模块 | 验收标准 | 优先级 |
|---|------|---------------|----------|--------|
| 1 | CacheEntry 记 `cwd`；维护 `cwdFirstLeaseAt`；淘汰路径改 `asyncDispose`（或 evict 时 await dispose） | `src/agentService.ts` | 同 cwd 多 agent 共享同一 `firstLeaseAt`；cwd 清空后键删除 | 必须 |
| 2 | `sendMessage` 入口：超龄才打租约 warn（含 ageMs） | 同上 | 健康路径无租约 info；超龄可见 flush warn（〈决策·lease-age-log〉） | 必须 |
| 3 | 超龄 flush 该 cwd 空闲句柄后再 create/resume | 同上 | 超龄后下一次 send 冷启动；`firstLeaseAt` 重置 | 必须 |
| 4 | 常量 `AGENT_EXECUTOR_MAX_AGE_MS` 默认 45min；supervisor/env 说明按需 | `agentService.ts`；可选 `deploy/supervisor.ini` | 默认 2700000（〈决策·max-age-45m〉） | 必须 |
| 5 | typecheck | — | `npm run typecheck` 通过 | 必须 |

### 4.2 测试要点

- [ ] 同 cwd 连续 send：健康路径无「executor 租约年龄」info。
- [ ] 手动把 `MAX_AGE` 调到极小（如 1s）后 send：应看到 flush warn（含 ageMs）+ 冷 resume/create，且新租约不再每条打 age。
- [ ] 一 agent busy 时另一同 cwd 触发限龄：busy 不被 dispose；有 warn。
- [ ] 换 cwd：各自独立的 `firstLeaseAt`，互不 flush。
- [ ] 回归：正常短会话、取消 run、删除会话、undo 仍可用。

### 5.1 已定决策 / 约束

| 名字 | 结论 | 来源 | 影响位置（改它要动哪） |
|------|------|------|----------------------|
| no-auth-fallback | 不根据 auth 失败自动 flush/重试；限龄是唯一主动恢复手段 | 用户 Phase 3 | §0、§3、任务#3 |
