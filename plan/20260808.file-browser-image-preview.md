# 文件浏览：常见位图缩略图预览

> **文档定位**：**活 spec**（会随实施反复更新）。
> 「关键决策与未决项」表是唯一真相源；正文引用它、不复述它。

## 0. 一页纸（骨架先行）

- **一句话**：在现有文件浏览 Overlay 上，为常见位图增加右栏缩略图预览（手机/桌面同一套前端），其它二进制与插入 `@路径` 行为不变。
- **承重决策**：
  1. **方案 A+（read 元信息 + raw 字节）** —— 点文件仍先走 `/api/fs/read`：合格图片返回 `kind: "image"` + URL；超限返回明确 `skipped`；字节由 `/api/fs/raw` 原生加载。因为 5MB 上限需要可读的跳过文案，且避免把大图塞进 JSON（详见 §3 / 〈决策·image-preview-a-plus〉）。
  2. **仅常见位图** —— 只预览 png/jpeg/webp/gif；svg 等仍按二进制跳过（详见 〈决策·image-preview-exts〉）。
  3. **图片独立 5MB 上限** —— 与文本 200KB/2000 行分立；用 `stat.size` 判定（详见 〈决策·image-preview-max-bytes〉）。
  4. **复用路径禁锢与 cookie 鉴权** —— raw 与 list/read 同一套 cwd 白名单 + realpath；`<img>` 靠已有 cookie 鉴权，不引入自定义 header（详见 〈决策·image-preview-secure-raw〉）。
  5. **插入路径与文本预览不动** —— 本能力只扩展预览渲染分支（详见 〈决策·image-preview-no-insert-change〉）。
- **验收总目标**：≤5MB 的常见位图在 Overlay 右栏以缩略图可见；超限/非目标类型有明确原因；文本预览、搜索、`@路径`、diff 互斥与 SSE 无回归。

## 1. 需求背景

### 1.1 原始需求

> 目前这的文件预览功能应该是不支持预览二进制内容的，但是我也希望在手机端能够有一定程度上的预览图片内容的能力。你帮我看一下怎么改比较好

后续确认：动机主要是手机点开仓库图片，同一套前端故 PC 一并支持；只做常见位图、缩略图即可；图片单独上限 5MB；插入路径不改；实现路径在 A（独立 raw URL）与扩展 read 之间无偏好，经评估选定 A+。

### 1.2 背景与动机

文件浏览 MVP 刻意不做图片预览（`〈决策·preview-langs〉`）。手机上核对截图/资源图时只能看到「二进制或图片文件，不展示内容」，缺少最低限度的可视确认。缩略图预览补齐这一缺口，不引入通用二进制 viewer。

### 1.3 目标与验收标准

- png / jpeg / webp / gif 且 ≤5MB：右栏缩略图可见（手机与桌面）。
- \>5MB：`too_large` 明确文案，不出现破图当成功。
- 非目标扩展名（含 svg/ico/bmp/avif 等）：仍 binary 跳过。
- 文本预览、搜索、插入 `@路径`、Overlay 互斥、SSE 生命周期无回归。
- 白名单外 cwd、逃逸路径：read 与 raw 均拒绝。

### 1.4 约束与前提

- 仍为无构建单页 + Express；不改 agent/run/SSE/composer 发图链路。
- 鉴权继续 cookie（浏览器原生 `<img>` 无法带自定义 Authorization）。
- 易变阈值（扩展名集合、5MB）只收口 §5，正文引用不复述。

## 2. 现状分析

### 2.1 相关代码/系统现状

- `src/fileBrowser.ts` 的 `readTextFile`：`IMAGE_EXTS`（含 svg 等）直接 `skipped: binary`；其它含 `\0` 亦 binary；文本另有行数/体积截断。
- `GET /api/fs/read` 只返回 JSON 文本或 skipped；无二进制出口。
- `public/fileBrowser.js`：`skipped` → 跳过文案；无 `<img>` 分支。
- 已有先例：`GET /api/user-images/:runId` 用 cookie + `Content-Type` + `sendFile` 供 `<img>` 加载。
- 手机 Overlay 已是上树下预览布局；缩略图主要靠 CSS。

### 2.3 现状与目标的差距

| 现在 | 目标 |
|------|------|
| 图片一律 binary skip | 常见位图缩略图 |
| 无受控二进制出口 | `/api/fs/raw` + 5MB 闸门 |
| `preview-langs`：图片不可预览 | 翻盘为位图可预览 |

### 2.4 影响范围

- 模块：`src/fileBrowser.ts`、`src/server.ts`、`public/fileBrowser.js`、少量 `public/style.css`；必要时 `public/api.js` 若封装 raw URL。
- 场景：文件浏览 Overlay 预览右栏；list/search/插入/chat/git 不在范围内。
- 无新外部 SDK。

## 3. 方案设计

### 方案 A：扩展名直出 `<img>` + `/api/fs/raw`（备选）

- **思路**：前端认扩展名后直接请求 raw；read 可不参与图片成功路径。
- **优点**：往返最少。
- **缺点**：超限/403 时 `img.onerror` 文案弱。
- **工作量**：S

### 方案 A+：read 元信息 + raw 字节（选定）

- **思路**：选文件仍先 `GET /api/fs/read`。若扩展名属于可预览位图：`stat` 后超限 → `skipped: too_large`；否则 → `content: null`、`skipped: null`、`kind: "image"`、`mimeType`、`url`（指向同 cwd/path 的 raw）。前端渲染缩略图。`GET /api/fs/raw` 再做禁锢 + 扩展名白名单 + 5MB + `Content-Type` 后 `sendFile`/等价流式发送。
- **改动范围**：`fileBrowser` 读路径与类型、server 新路由、前端预览分支与 CSS。
- **优点**：超限文案与现有 skipped UX 一致；伪造扩展名/非文件可在 read 阶段暴露；字节不进 JSON。
- **缺点**：成功预览多一次轻量 JSON（可接受）。
- **工作量**：S～M

### 方案对比

| 维度 | A | A+ |
|------|---|-----|
| 超限文案 | 弱 | 强 |
| JSON 体积 | 无大图 | 无大图 |
| 契约改动 | 几乎只加 raw | read 增 `kind` 等字段 |
| 与 Overlay 现流 | 前端旁路 | 仍先 read 再画 |

### 最终选定

**方案 A+**（用户 Phase 3 确认）。

### 执行步骤

原则：先后端契约可手测，再接线前端；安全校验与文本路径共用，避免第二套禁锢。

1. **后端图片集合与 read 分支** —— 从原 `IMAGE_EXTS` 拆出「可预览位图」与「仍当二进制」；read 对前者走 stat → skipped / kind+url，对后者保持 binary skip。先改契约，便于 curl 验收（详见 〈决策·image-preview-exts〉〈决策·image-preview-a-plus〉）。
2. **挂 `GET /api/fs/raw`** —— `assertAllowedCwd` + 与 read 同一 `resolveWithinCwd`；再校验扩展名与 5MB；设置 `Content-Type` 后发送文件。与 user-images 同属「cookie 可加载的二进制」（详见 〈决策·image-preview-secure-raw〉）。
3. **前端预览分支** —— `kind === "image"` 时渲染 `<img>` 缩略图；保留 `requestSeq` 防串图；`onerror` 显示无法加载；插入按钮逻辑不动（详见 〈决策·image-preview-no-insert-change〉）。
4. **CSS** —— 右栏图片 `max-width`/`max-height` 适应预览区，避免撑破 Overlay（手机上半树半预览尤需）。
5. **决策与 typecheck** —— 翻盘 `preview-langs`；`npm run typecheck`；手测验收清单。

### 压力测试

| 压力维度 | 具体场景 | 方案表现 | 是否需要防御性设计 |
|----------|---------|----------|------------------|
| 故障容错 | 扩展名是 png、内容不是图，或 read 与 raw 间文件消失 | raw 再校验；`<img onerror>` 明示失败 | 是 |
| 规模压力 | 贴边 5MB、快速连点多图 | raw 流式；read 只 stat；`requestSeq` 作废旧响应 | 是（沿用现有 seq） |
| 安全 | `..` / symlink 逃逸 | 与 list/read 同一禁锢 | 是：复用 resolve |
| 演进 | 以后要 PDF/SVG | `kind` + 扩展名白名单可扩；MVP 不做 viewer | 否（记演进方向即可） |

### 4.1 子任务拆解

| # | 任务 | 涉及文件/模块 | 验收标准 | 优先级 |

| 5 | typecheck + 手测 | — | §4.2 清单通过 | 必须 |

### 4.2 测试要点

- [ ] ≤5MB 的 png/jpeg/webp/gif：右栏缩略图（桌面 + 窄屏）
- [ ] \>5MB 图片：too_large 文案，无「成功破图」
- [ ] svg（及其它原 IMAGE 但非预览集合）：仍 binary 文案
- [ ] 普通 `.py`/`.md` 预览与搜索无回归
- [ ] 选中图片后「插入 @路径」仍可用且语义不变
- [ ] 非白名单 cwd / 逃逸 path：read 与 raw 均拒绝
- [ ] Overlay 打开期间 SSE 仍不 detach；与 diff 互斥不变
