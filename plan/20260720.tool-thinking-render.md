# 工具调用与思考块渲染优化

> **文档定位**：**活 spec**（会随实施反复更新）——「关键决策与未决项」表是唯一真相源，正文引用它、不复述。

## 0. 一页纸（骨架先行）

- **一句话**：前端把工具折叠条从 JSON 预览改成人话摘要，常用工具（含 glob）展开后按类型美化；思考默认折叠；轮次整包折叠保留。
- **承重决策**：
  1. **只改前端** —— 不碰 SSE / runHub / history 协议，因为数据已够用，痛点在展示（详见 〈决策·frontend-only〉）。
  2. **抽出 `toolFormat.js`** —— 摘要与详情 HTML 与 DOM 装配分离，加工具只扩格式表（详见 〈决策·tool-format-module〉）。
  3. **常用工具优先、其余 JSON** —— grep/read/edit/shell/glob（及 createPlan）走人话+美化，未知/畸形兜底现有 JSON（详见 〈决策·four-tools〉、〈决策·glob-format〉）。
  4. **思考默认折、条上只写「思考」** —— 用户对思考兴趣低，直播也不自动撑开（详见 〈决策·thinking-collapse〉）。
  5. **整包折叠保留** —— 「中间过程 · N 项」语义不变，单条折嵌在整包内（详见 〈决策·keep-group-collapse〉）。
- **验收总目标**：移动端折叠条一眼能辨工具与对象；展开常用类型可读；思考默认合；整包行为与现在一致；畸形 payload 不白屏。

## 1. 需求背景

### 1.1 原始需求
> 优化 AI Assistant 中间工具调用的渲染。常见的有 grep/read/edit/shell。另外思考也想优化一下，有些 AI 的思考可能比较长，需要进行折叠。

补充确认：主要痛点是扫一眼看不出在干什么，尤其移动端宽度有限，折叠横条被空格和引号占据；折叠条要人话摘要，展开按类型美化；思考默认折叠；整包折叠保留；优先覆盖上述四类工具。

### 1.2 背景与动机
当前工具卡用 `JSON.stringify(args)` 做一行预览，在窄屏上几乎只剩引号与空白。思考块全文铺开，长思考占屏，而用户对思考过程兴趣不高。轮次级「中间过程」整包折叠已经存在，需要保留。

### 1.3 目标与验收标准
- 常用工具折叠条为人话摘要（路径短、无 JSON 引号墙），移动端可扫读。
- 展开后：shell 看 stdout/stderr/exitCode；read 看内容；grep 看命中列表；edit 看 diff（含简易行色）；glob 看 pattern + 文件列表；其它工具仍 JSON。
- 思考默认折叠，点开全文；直播生成时条保持合着。
- 「中间过程 · N 项」默认折、点开露出内部单元，行为与现网一致。
- args/result 缺字段或未知工具时退回 JSON，不白屏。

### 1.4 约束与前提
- 仅前端（详见 〈决策·frontend-only〉）。
- 美化不上 CDN 语法高亮（详见 〈决策·beautify-depth〉）。
- edit 的 args 通常只有 `path`，改动内容在 `result.value.diffString`（详见 〈决策·edit-shape〉）。

## 2. 现状分析

### 2.1 相关代码/系统现状
两条入口汇到同一套 DOM 构造：

- **历史**：`/api/conversation` → `renderHistory` → `appendStepsWithCollapse` → `renderConversationStep` → `appendToolBlock` / `appendThinkingBlock`。
- **直播**：SSE → `handleStreamEvent` → `updateToolBlock` / `appendThinkingTextDelta`；`done` 时 `collapseCurrentTurnMiddle` 把除最后一项外收进整包。

工具条预览由 `summarizeArgs` 把 args `JSON.stringify` 后截断；详情区是原始 Args/Result JSON。思考在历史路径是斜体全文块；直播路径在 `stream.js` 手写 `.block-thinking` DOM，与 `appendThinkingBlock` 不一致。整包 UI（`.block-group`）已存在。

工具身份：历史用 `step.message.type`，直播用 `event.name`，语义对齐，格式化前归一为同一 `name` 即可。

### 2.2 现状与目标的差距

| 目标 | 现状 | Gap |
|------|------|-----|
| 人话摘要 | JSON 一行预览 | 缺按工具取关键字段 + 路径缩短 |
| 类型美化 | 纯 JSON | 缺四类分支与截断 |
| 思考默认折 | 全文展开；直播双路径 | 统一可折叠块；直播不自动撑开 |
| 整包保留 | 已有 | 无 gap；注意嵌套点击不互抢 |

### 2.3 影响范围
- **必改**：`public/render.js`、`public/stream.js`、`public/style.css`；新建 `public/toolFormat.js`。
- **不动**：后端、`runHub`、SSE 事件形状、整包折叠语义。
- **回归面**：历史重渲、直播 running→completed、done 后 refetch、整包与单条嵌套开合、未知工具兜底。

## 3. 方案设计

### 方案 A：在 `render.js` 内扩展
- **思路**：直接改 `summarizeArgs` / tool/thinking 装配与 CSS。
- **改动范围**：`render.js` + `stream.js` + `style.css`。
- **优点**：文件少。
- **缺点**：`render.js` 继续膨胀；加工具更挤。
- **工作量**：S～M

### 方案 B：抽出 `toolFormat.js`（选定）
- **思路**：纯函数模块负责摘要字符串与详情 HTML；`appendToolBlock` / `updateToolBlockEl` 只负责 DOM 与开合；思考折叠统一进 `appendThinkingBlock`，直播改走同一 API。
- **改动范围**：+`toolFormat.js`，改上述三文件。
- **优点**：类型逻辑与装配分离；和「四类优先、其余 JSON」边界清晰。
- **缺点**：多一个文件。
- **工作量**：M

### 方案 C：B + 产品级高亮/完整 diff
- **思路**：同 B，read/shell 接 CDN 高亮，edit 做更重的 diff UI。
- **优点**：展开最好看。
- **缺点**：依赖与截断策略更重；主痛点在折叠条，收益不对齐。
- **工作量**：M～L

### 方案对比
| 维度 | A | B | C |
|------|---|---|---|
| 改动范围 | 3 文件 | 4 文件 | 4 文件 + 高亮深度 |
| 回归风险 | 低 | 低 | 中 |
| 横条可读性 | 达标 | 达标 | 达标 |
| 后续加工具 | 一般 | 最好 | 好但更重 |
| 工作量 | S～M | M | M～L |

### 最终选定
**方案 B**，因为痛点在折叠条摘要与结构清晰度，展开用结构化 pre + edit 简易行色足够（结论一句话，详见 〈决策·tool-format-module〉、〈决策·beautify-depth〉）。

### 执行步骤
原则：先纯函数、再接线、再统一思考、最后样式与手测——可失败/可单测的逻辑前置，DOM 与双路径收口殿后。

1. 新增 `public/toolFormat.js`：`summarizeTool(name, args, result)`、`renderToolDetail(name, args, result)`；常用工具分支（含 glob）+ 默认 JSON；路径相对化/basename；长文本截断标记——先定格式契约，避免一边改 DOM 一边猜字段。
2. 改 `appendToolBlock` / `updateToolBlockEl` 调用 format；更新摘要时尽量保留详情开合状态——行为面立刻改善且不动整包。
3. `appendThinkingBlock` 改为默认折叠（条上仅「思考」）；可选流式追加正文到折叠体的 API——历史路径先通。
4. `stream.js` 删除手写 thinking DOM，改走统一 API；直播中条保持合着——消灭双路径（结论一句话，详见 〈决策·thinking-collapse〉）。
5. CSS：思考折叠头、详情区、edit 行色、`max-height` 滚动。
6. 手测验收清单（见 §4.2）。

### 压力测试（残余风险）

| 压力维度 | 具体场景 | 方案表现 | 是否需要防御性设计 |
|----------|---------|----------|------------------|
| 故障容错 | args/result 缺字段或形状突变 | 该条退回 JSON | 是：每类分支 try/防御式取值 |
| 规模 | 大 stdout / 大 content / 长 diff | 撑爆展开区 | 是：max-height + 截断文案 |
| 嵌套折叠 | 整包内点单条 header | 可能误触整包 | 是：单条 click 不冒泡 |
| 直播时序 | running→completed 补 result | edit 摘要可补 +N/-M | 是：update 时重算摘要与详情 HTML |
| 演进 | 新增 ls 等 | 改 format 表即可 | 已由模块边界覆盖；glob 已落地（〈决策·glob-format〉） |
