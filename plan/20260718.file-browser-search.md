# 文件浏览 Overlay：按相对路径子串搜索

> **文档定位**：**活 spec**（会随实施反复更新）。
> 「关键决策与未决项」表是唯一真相源；正文引用它、不复述它。
> 本能力叠在既有文件浏览 Overlay 之上（见 `plan/20260718.file-browser-overlay.md`），不改 agent / SSE / `@` 插入协议。

## 0. 一页纸（骨架先行）

- **一句话**：在文件浏览 Overlay 顶栏加搜索框，回车后由服务端在 cwd 内按**相对路径子串**（不区分大小写）递归扫描，左栏切成命中扁列表；清空后恢复懒加载树根——解决「未展开就找不到深层文件」的问题。
- **承重决策**（3~5 条）：
  1. **同模块同步 walk + `GET /api/fs/search`（方案 A）** —— 无新依赖，与 list/read 共用 path-confine；单用户可接受最多约 5s 占事件循环（详见 §3 / 〈决策·sync-walk〉）。
  2. **匹配相对路径子串、只返回文件** —— 对 `path.relative(cwd, abs)` 做 `toLowerCase().includes(q)`；目录可扫但不进结果（详见 〈决策·match-relpath〉〈决策·files-only〉）。
  3. **四闸截断 + banner** —— 命中 100、扫描节点 5 万、深度 12、墙钟 ≤5s；超限停止并用 banner 说明原因（详见 〈决策·search-caps〉）。
  4. **左栏双态：树 ↔ 扁列表** —— Enter 出结果；空串/清空回 `loadRoot`；不扩树高亮（详见 〈决策·flat-results〉〈决策·clear-restores-tree〉）。
  5. **安全与主链不动** —— cwd 白名单 + path-confine + hide-dot；预览/插入/`keep-stream`/与 diff 互斥沿用既有 Overlay（详见 〈决策·reuse-overlay-contract〉）。
- **验收总目标**：能在限深限量内用回车搜到相对路径命中文件并预览/插入 `@绝对路径`；超限有 banner；清空回树；不破坏懒加载浏览与 SSE。

## 1. 需求背景

### 1.1 原始需求

> 给文件浏览器增加搜索：输入关键字，在文件夹树里筛出命中关键字的文件列表。按方案 B（整棵 cwd 服务端按名/路径搜，非仅滤已加载节点）出方案。

后续确认：匹配**相对路径片段**、子串、不区分大小写；结果 UI **扁列表**；命中上限 100、扫描节点 5 万、深度 12、≤5s；超限 banner 即可；搜索框在 Overlay **顶栏**；**回车**搜索；清空后恢复懒加载树根。实现选定同模块同步 walk（方案 A）。压测补丁：空白查询不发起 search、直接回树；坏节点跳过；Esc 优先清搜索再关 Overlay。深度/节点/墙钟曾按 3 / 1 万 / 2s 落地，后因 `pkg/.../resources/*.go` 一类路径搜不到而放宽（见 §5.1）。

### 1.2 背景与动机

既有 Overlay 是懒加载树（`决策·lazy-tree`）：未展开的深层文件前端根本没有路径。要「敲关键字找到文件再插 `@路径`」，必须服务端递归扫描；扁列表比扩树高亮改动小、和现有左栏模型好切。

### 1.3 目标与验收标准

- 顶栏有搜索框；Enter 触发搜索（〈决策·search-on-enter〉）。
- 命中展示为左栏扁列表（相对路径可见、选中仍用绝对路径预览/插入）（〈决策·flat-results〉）。
- 四闸与 banner 按 〈决策·search-caps〉。
- 清空/空白 Enter → 懒加载树根（〈决策·clear-restores-tree〉）。
- 预览、插入 ` @绝对路径 `、关 Overlay、与 diff 互斥、不 detachStream 行为不变（〈决策·reuse-overlay-contract〉）。
- 白名单外 cwd、逃逸路径被拒；点开头项不进扫描结果（复用既有 fs 决策）。

### 1.4 约束与前提

- 不做文件**内容**全文检索（〈决策·no-content-search〉）。
- 不引入前端 npm / 新系统依赖；不改 agent/run/SSE/`/api/chat`。
- 易变上限数字只收口 §5，正文不复述多份。
- 叠在已落地的 file-browser Overlay 上；list/read 契约保持兼容。

## 2. 现状分析

### 2.1 相关代码/系统现状

- **后端**：`src/fileBrowser.ts` 仅有 `listDirectory`（单层）与 `readTextFile`；`resolveWithinCwd` 已实现 path-confine；hide-dot / list-cap / truncation 已钉死。
- **HTTP**：`GET /api/fs/list`、`GET /api/fs/read`；共用 `assertAllowedCwd`。
- **前端**：`public/fileBrowser.js` 维护 `open` / `openCwd` / `requestSeq` / 懒加载树 DOM；顶栏目前只有文件夹名与关闭按钮（`index.html`）；无搜索态。
- **插入与 Overlay 契约**：光标插入、close-on-insert、overlay-mutex、keep-stream 已在既有活 spec 与代码旁 `决策·` 注释中。

### 2.3 现状与目标的差距

| 目标 | 现状 | Gap |
|------|------|-----|
| cwd 内相对路径子串搜索 | 无 | `searchFiles` + `/api/fs/search` |
| 左栏扁列表结果态 | 只有树 | 双态渲染与切换 |
| 顶栏回车搜索 / 清空回树 | 无输入框 | HTML + 事件 + Esc 优先级 |
| 四闸截断与超时 | 仅单目录 list-cap | walk 内计数/深度/墙钟 |

### 2.4 影响范围

- **会改**：`src/fileBrowser.ts`、`src/server.ts`、`public/api.js`、`public/fileBrowser.js`、`public/index.html`、`public/dom.js`、`public/style.css`；本文件。
- **基本不动**：`agentService` / `runHub` / `history` / 发消息与 SSE；`read` 预览与插入逻辑（搜索结果行复用 `selectFile` / `insertSelectedPath`）；`gitDiff` 互斥接线（最多无改动）。
- **文档**：本文件为搜索能力真相源；原 file-browser Overlay 活 spec 不把搜索决策复制进去，避免双处维护。

## 3. 方案设计

### 方案 A：同模块同步 walk + `GET /api/fs/search`（选定 / 推荐）

- **思路**：在 `fileBrowser.ts` 增加递归 walk（BFS 或 DFS 均可，须统一深度语义）；对每个**文件**用相对 cwd 的路径做大小写不敏感子串匹配；收集至多 100 条；节点访问达 5 万、深度超过 12、或墙钟超过 5s 则停止并标记截断原因。前端顶栏 input，Enter 调 API，左栏换成扁列表；空查询或清空则 `loadRoot`。点行仍走现有 read / 插入。
- **改动范围**：见 §2.4。
- **优点**：无新依赖；安全与 list/read 同模块；产品行为与 Phase 1 一致。
- **缺点/风险**：walk 期间最多约 5s 阻塞该 Node 事件循环（单用户自托管可接受；〈决策·sync-walk〉）。
- **工作量**：M

### 方案 B：子进程 `find` / `rg --files`（未选）

壳出去扫路径。大树可能更快，但转义/平台/与四闸对齐更烦，失败面更多。

### 方案 C：分块 walk + `setImmediate`（未选）

减轻事件循环占用，实现与取消更绕；对本 MVP 收益不足以抵复杂度。

### 方案对比

| 维度 | A 同步 walk | B 子进程 | C 分块 walk |
|------|-------------|----------|-------------|
| 回归风险 | 低 | 中 | 低～中 |
| 依赖 | 无 | 外部二进制 | 无 |
| 工作量 | M | M | M+ |

### 最终选定

**方案 A**，用户 Phase 3 明确选定。

### 执行步骤

原则：**先后端契约与四闸，再路由，再顶栏与双态 UI，最后 Esc/过期请求与回归；全程不碰 stream。**

1. **`searchFiles(cwd, query)`** —— 复用 path-confine 解析 cwd；query trim 后小写；walk 时跳过点开头名；坏目录/坏 symlink **跳过继续**（〈决策·skip-bad-nodes〉）；深度按 〈决策·depth-semantics〉；只把文件写入 matches；对外 `path` 为绝对路径，列表展示可用 `relativePath`；返回 truncated + truncateReason（hit_limit / node_limit / depth 不单独作为全局停止原因时也可只在达到深度时不下行，全局停用 node/hit/timeout）（〈决策·search-caps〉）。
2. **`GET /api/fs/search?cwd=&q=`** —— `assertAllowedCwd`；缺 q 或纯空白由前端不调用（若误调可 400）；PathConfineError → 403。
3. **顶栏搜索框** —— 放在 Overlay header（标题与关闭之间或标题行内）；`dom.js` 导出；样式克制，对齐现有 panel。
4. **左栏双态** —— `tree`：现有懒加载；`results`：扁列表（展示 relativePath，dataset 仍用绝对 path）；Enter：有内容则 search，无内容则回树（〈决策·empty-query-resets〉）；清空控件同效（〈决策·clear-restores-tree〉）。
5. **Banner / seq / Esc** —— 截断原因写 banner；`requestSeq`+`openCwd` 丢弃过期响应；Esc：若有查询内容或处于结果态则先清空回树，否则关 Overlay（〈决策·esc-clears-search-first〉）。
6. **回归** —— 懒加载、预览、插入、mutex、keep-stream、切 cwd 关/重开行为未被破坏。

### 压力测试

| 压力维度 | 具体场景 | 方案表现 | 是否需要防御性设计 |
|----------|---------|----------|------------------|
| 故障容错 | 不可读子树 / 坏 symlink | 跳过继续，不整请求失败 | 是：〈决策·skip-bad-nodes〉 |
| 规模压力 | 超大仓库 / 命中极多 | 四闸停止 + banner | 是：〈决策·search-caps〉 |
| 操作风险 | 搜索中关 Overlay、切 cwd、连按 Enter | 过期结果串入 UI | 是：既有 seq/cwd；结果态同样遵守 |
| 与对话并存 | 搜索 walk 占事件循环 | 其它 API 最多卡 ~5s | 接受：〈决策·sync-walk〉；不做 C |
| Esc 误关 | 搜完想清条件却关掉 Overlay | 丢上下文 | 是：〈决策·esc-clears-search-first〉 |

## 5. 关键决策与未决项（唯一真相源）

### 5.1 已定决策 / 约束

| 名字 | 结论 | 来源 | 影响位置（改它要动哪） |
|------|------|------|----------------------|
| sync-walk | 在 `fileBrowser.ts` 内同步递归 walk，不另起子进程、不分块让出；可接受 ≤5s 占事件循环 | 用户 Phase 3 选 A；后放宽墙钟 | §3、任务#1 |
| match-relpath | 对相对 cwd 的路径字符串做大小写不敏感子串匹配（`includes`）；不是只匹配 basename，也不是 glob | 用户 Phase 1 | 任务#1 |
| files-only | 结果只含普通文件；目录参与 walk/计数，但不进 matches | 用户 Phase 2 确认默认 | 任务#1、#4 |
| depth-semantics | 深度 12 = 从 cwd 起最多再下钻 12 层（`cwd/a/…/l` 可扫到文件，再深一层目录不进入） | 用户 Phase 2 默认 3；因深层包路径搜不到放宽为 12 | 任务#1 |
| search-caps | 命中上限 100；扫描节点上限 50000（仅计通过 hide-dot 过滤后、实际 visit 的文件+目录）；墙钟超时 5000ms；深度按 depth-semantics 不再下行。任一命中上限/节点上限/超时触发即停止；超限 banner 写明原因 | 用户 Phase 1；压测；后放宽节点/墙钟 | 任务#1、#5 |
| flat-results | 搜索成功后左栏为扁列表（展示 relativePath），不是扩树高亮 | 用户 Phase 1 | 任务#4 |
| search-on-enter | 仅回车触发搜索，不做输入防抖即时搜 | 用户 Phase 1 | 任务#4 |
| clear-restores-tree | 清空搜索后恢复懒加载树根（`loadRoot`），不保留搜索前展开态 | 用户 Phase 1 | 任务#4 |
| empty-query-resets | trim 后空字符串：不调用 search API，直接回树态 | Phase 3 压测 | 任务#4 |
| skip-bad-nodes | walk 遇不可读/坏 symlink 等跳过该节点继续，不整请求 500 | Phase 3 压测 | 任务#1 |
| esc-clears-search-first | Esc：若搜索框有内容或左栏为结果态 → 清空并回树；否则关闭 Overlay | Phase 3 压测 | 任务#5 |
| no-content-search | 本方案不做文件内容全文检索 | 用户可行性讨论 | §1.4 |
| reuse-overlay-contract | 预览/插入/close-on-insert/mutex/keep-stream/cwd 白名单/path-confine/hide-dot/abs-path 全部沿用 file-browser Overlay；搜索只多一条读 API 与左栏模式 | 既有活 spec + 用户约束 | 全局 |
| search-api | `GET /api/fs/search?cwd=&q=`；响应含 matches（name/path/relativePath）、truncated、truncateReason（有则） | Phase 3 | 任务#2 |
| header-search-ui | 搜索框放在 Overlay 顶栏（header 区域） | 用户 Phase 1 | 任务#3 |
