# SDK Shell / 模型可见 cwd 与 local.cwd 对齐

> **文档定位**：**活 spec**（会随实施反复更新）。
> 「关键决策与未决项」表是唯一真相源；正文引用它、不复述它。

## 0. 一页纸（骨架先行）

- **一句话**：`@cursor/sdk` 本地运行时里，Grep/Glob 等走 `local.cwd`，但 Shell 粘性目录与模型侧 `processWorkingDirectory` 绑在服务进程 `process.cwd()`（Supervisor 钉在本仓库），造成「工具工作区对、Shell/自述错」。用 patch-package 把这两处接到工作区路径上。
- **承重决策**：
  1. **方案 A：patch SDK** —— 不劫持/`chdir` 全局 cwd，因多文件夹并发与已证失败（详见 §3 / 〈决策·patch-sdk〉）。
  2. **Shell 用 `clone(c)`** —— 在包进 `Ns` 前对 terminal executor `clone(工作区路径)`，校正 sticky cwd（详见 〈决策·shell-clone〉）。
  3. **模型可见目录改注入** —— `processWorkingDirectory` 优先 `workspacePaths[0]`（详见 〈决策·model-pwd〉）。
  4. **重启仅用户执行** —— 补丁后须重启 Supervisor 清 executor 租约；**禁止 AI 重启**，以免杀掉自身会话（详见 〈决策·user-restart〉）。
  5. **不管 cd 粘性 / 后台 shell** —— 只保证初始工作目录 = 启动 `local.cwd`（详见 〈决策·scope-initial-cwd〉）。
- **验收总目标**：非本仓库会话中，Shell `pwd` 与模型自述工作目录均等于启动文件夹；Grep/Glob 不回归；本仓库会话无回归。

## 1. 需求背景

### 1.1 原始需求

> 其它项目 Agent 会话里，Shell 看到的工作目录是本 Cursor 服务目录；Grep/Glob 等却是启动 SDK 时传入的目标目录。需要模型看到的所有工作目录都与启动文件夹一致。cd/粘性/后台 shell 超出初始工作目录的不管。先前 `chdir` 修法无效已撤销。

### 1.2 背景与动机

单进程托管多白名单文件夹；Supervisor `directory=` 固定为本仓库。会话 UI/传参已正确，分裂来自 SDK 内部双轨 cwd，导致相对路径 Shell 与模型情境错位。

### 1.3 目标与验收标准

- 新建非本仓库会话：`pwd` = 该会话 `cwd`。
- 模型自述/可见工作目录与启动 `cwd` 一致。
- 同会话 Grep/Glob 仍落在该 `cwd`。
- 本仓库会话行为不变。
- 不测：跨命令 `cd` 粘性、后台 shell（〈决策·scope-initial-cwd〉）。

### 1.4 约束与前提

- 本仓库已正确传 `Agent.create/resume({ local: { cwd } })`；问题不在业务传参。
- 已有 `patch-package` 流程（stall 补丁）；本需求同一运维模式（〈决策·patch-sdk〉）。
- 部署后清旧 executor 租约必须重启进程，且**只能用户操作**（〈决策·user-restart〉）。

## 2. 现状分析

### 2.1 相关现状

- **本仓库**：`agentService` 创建/续聊传 `local.cwd`；Supervisor 钉服务所在仓库目录。
- **SDK `@cursor/sdk@1.0.23`**：`getExecutor` 把 `local.cwd` 建成 LocalExecutor `workingDirectory` → `workspacePaths`（Grep/Glob/读写正确）。
- **Shell**：`Fn({env, userTerminalHint})` 不传 cwd；bash/zsh dump spawn 无 `cwd`，继承 `process.cwd()`；`getCwd()` 成 Shell 默认目录。`Ns` 虽持有正确 `workspacePath`，但默认仍 `workingDirectory || executor.getCwd()`，绝对错误路径不会被纠正。
- **模型侧**：环境注入 `processWorkingDirectory: process.cwd()`（`357.js` 仅一处），与 `local.cwd` 无关。
- **已否决**：短窗 `process.chdir`——dump 懒加载常在 `send` 窗口外；且改不干净模型注入。

### 2.2 问题定位

- **类型**：上游 SDK 契约缺口（本仓库放大：进程 cwd ≠ 会话 cwd）。
- **根因**：Shell sticky cwd + `processWorkingDirectory` 未接线 `workingDirectory` / `workspacePaths`。

### 2.3 Gap

| 目标 | 现状 |
|------|------|
| Shell 初始目录 = `local.cwd` | = 服务 `process.cwd()` |
| 模型可见工作目录 = `local.cwd` | = `process.cwd()` |
| Grep/Glob = `local.cwd` | 已正确，需保持 |

### 2.4 影响范围

- **会改**：`node_modules/@cursor/sdk/dist/esm/357.js`（仅 esm，与现有 stall patch 一致）；`patches/@cursor+sdk+1.0.23.patch`；`docs/cursor_sdk_patches.md`。
- **不改**：`agentService` 业务逻辑、前端、Supervisor 配置（重启由用户做）。

## 3. 方案设计

### 选定：方案 A — patch SDK 两处接线

- **思路**：
  1. 建 Shell 时先算单工作区路径 `c`，再 `terminalExecutor ?? Fn(...)`，`c` 非空则 `.clone(c)`，再交给 `Ns`（〈决策·shell-clone〉）。
  2. `processWorkingDirectory` 改为优先 `workspacePaths[0]`，否则回退 `process.cwd()`（〈决策·model-pwd〉）。
- **备选未选**：ALS 劫持 `process.cwd()`（全局猴补丁、覆盖面难证）；`chdir`（已失败）。
- **伪代码**（示意，非权威实现）：

```text
c = singleWorkspacePath(...)   // 现有逻辑
s0 = terminalExecutor ?? Fn({ env, userTerminalHint })
s  = c ? s0.clone(c) : s0      // 仅 c 非空
wrap Ns(s, ...)
// 另：processWorkingDirectory = workspacePaths[0] ?? process.cwd()
```

### 压力测试残余（须显式兜底）

| 场景 | 表现 | 防御 |
|------|------|------|
| `c` 为空（多 root dirname 不一致） | 本产品单 cwd 走不到；误 `clone(undefined)` 危险 | 仅非空字符串才 clone（〈决策·shell-clone〉） |
| 打补丁前已缓存的 executor | 旧 sticky 不自愈 | 用户重启 Supervisor（〈决策·user-restart〉） |
| SDK 升级 | chunk/压缩名变 | `docs/cursor_sdk_patches.md` 定位串 + 重打 patch |
| dump 仍在服务目录执行 | 只影响 state 快照来源，cwd 已正 | 知情接受（〈决策·dump-residual〉） |
