# 安卓薄壳：多 origin 列表切换

> **文档定位**：**活 spec**（会随实施反复更新）。「关键决策与未决项」表是唯一真相源；正文引用它、不复述它。
> 与 `plan/20260820.android-d2-native-shell.md` 并列：D2 管锁屏直播/TTS；本文只管**一份 APK 在多套局域网部署之间挑选当前入口**。

## 0. 一页纸（骨架先行）

- **一句话**：设置页维护约 3 个 http(s) 服务地址，点选后**同一块 WebView** 加载该站并卸掉旧站；前端假定同源同版本，壳不按站点分叉。

- **承重决策**（权威结论见 §5）：
  1. **只做设置页列表 + 当前 origin**，主界面不设标签/快捷切换——切换是偶发换部署，不是浏览多页（详见〈决策·settings-only〉）。
  2. **存储纯 URL 数组 + 当前项**，不要显示名——三条地址靠 URL 辨认即可（详见〈决策·url-only〉）。
  3. **壳 busy（现为 Run watch）时禁止改当前 origin**——否则 SSE 重试会打到新站 + 旧 agentId（详见〈决策·busy-gate〉）。
  4. **切站必须清 WebView 历史**——否则系统返回键会绕过设置回到上一台机器（详见〈决策·clear-history〉）。
  5. **不改网页协议、不保活多 WebView**——与 D2〈决策·webview-ui〉一致，只扩展〈决策·server-origin〉从「一个可编辑字符串」到「列表里的当前项」。

- **验收总目标**：侧载同一 APK，能在约 3 个 LAN 入口间点选切换；忙时切不过去并有说明；切走后返回键不串站；覆盖安装仍打开升级前那个 origin。

## 1. 需求背景

### 1.1 原始需求

> 给安卓 APP 设置多网页切换的功能，就是在设置页面可以去输入多个服务器的地址，然后方便在不同的服务器之间进行切换。理论上来说，不同服务器的前端版本都是一致的，也就是 WebView 的那一套是一致的。

补充（用户确认）：动机是局域网多套部署；点一项即切、主界面仍一个 WebView；切走后旧站卸掉；进行中的 run / TTS 时阻止切换；只允许 http(s)；大约存 3 个地址。

### 1.2 背景与动机

家里/内网会同时跑多份 cursor-web-chat（不同机器、不同 cwd），前端同版本。壳现在只有一个 `server_origin`，换站只能改掉那一格，不能记住几套入口。需要的是**通讯录式 origin 列表**，不是浏览器多标签。

### 1.3 目标与验收标准

见 §0 与 §4.2。

### 1.4 约束与前提

- 不改 `@cursor/sdk` 主循环、不新增 agent 协议（静态前提）。
- 对话 UI 仍是现有 `public/` 经 WebView 加载（与 D2 相同）。
- 单用户侧载；条目量按「大约 3」设计，不为上百条做分页。
- TTS 原生 Session **尚未落地**；busy 口径预留并入，本迭代只接 Run watch（详见〈决策·busy-gate〉）。
- `127.0.0.1` 继续拒绝：手机访问不到本机回环（沿用现校验）。

## 2. 现状分析

### 2.1 相关代码/系统现状

- `AppSettings` 单键 `server_origin`，默认现网网关；`MainActivity` 一块 WebView，`onResume` 发现 origin 变了就 `loadUrl`（旧文档已卸掉，但**历史栈仍可能留下上一 origin**）。
- 设置页单行输入 + 保存 + 刷新。
- `RunWatchService` 每次 `connect` 现读 `AppSettings.origin()`；无对外 busy 查询。页面经 `CwcNative.watchRun` 拉起 watch。
- Cookie 按 URL 存在 `CookieManager`，OkHttp 共用；换 host 不会串 `cwc_auth`。卸页不等于登出，切回 A 站仍可用 A 的 cookie。

### 2.2 现状与目标的差距

缺的是列表、当前项、忙时闸门、切站清历史；不是第二套 WebView 引擎。今日改 origin 与 watch 并发时，重试会用**新 origin + 旧 agentId**——闸门是正确性，不只是体验。

### 2.3 影响范围

- **改**：`AppSettings`、`SettingsActivity` + `activity_settings.xml` + `strings.xml`、`RunWatchService`（busy 暴露）、`MainActivity`（切站清历史）。
- **不改**：Express、`public/`、cookie 策略、FGS 类型、D2 的 Run/TTS 产品语义。
- **文档**：本文独立；实施时可在 `AGENTS.md` 能力表加一行指向本文。

## 3. 方案设计

### 方案 A：设置页 URL 列表，点选即切（选定）

- **思路**：SharedPreferences 存规范化 URL 数组 + 当前 origin。设置页列出已保存项（当前项标记），点非当前且非 busy → 写入当前 origin → `finish()`；主界面沿用 origin 变化则加载，并清历史。底部添加；只能删**非当前**项；列表不得空（空则回落默认网关）。
- **改动范围**：见 §2.3。
- **优点**：与已确认需求一一对应；加载路径已存在，增量小。
- **缺点**：无别名，相近 IP 靠 URL 辨认；每次切换进设置。
- **工作量**：S。

### 方案 B / C（未选）

B 为每条加显示名；C 为主界面再加快捷切换。用户 2026-08-20 选 A，不为 LAN 三条地址加字段或主界面壳控件。

### 最终选定

**方案 A**。

### 执行步骤

原则：**先能安全改 current（迁移 + busy + 清历史），再铺设置页 UI。** 闸门若不先于 UI，列表一点选就会串站。

1. **存储与迁移** —— 数组 + 当前项；读路径把旧单键迁进列表（覆盖安装不丢入口）。规范化与现网一致：`trim`、去尾 `/`。
2. **busy** —— watch map 增减时更新可查询的 busy；`setCurrent` / 点选前当场检查，禁止用「打开设置那一刻」的缓存。
3. **MainActivity 清历史** —— 仅当本次加载是**当前 origin 变更**（不是同站刷新）时，在 `onPageFinished` 后 `clearHistory`。同站刷新不清，以免破坏站内后退。
4. **设置页** —— 列表、点选、添加、删非当前、busy Toast（说明先等结束或点停止）。
5. **AGENTS.md 一行**（实施时）—— 指向本文，避免只在 D2 里找壳能力。

### 压力测试（残余风险）

| 压力维度 | 具体场景 | 防御 |
|----------|----------|------|
| 故障容错 | 只 `loadUrl` 不清历史 | 〈决策·clear-history〉 |
| 故障容错 | 删掉当前项或清空列表 | 〈决策·keep-one〉 |
| 故障容错 | busy 口径看 DOM 停止按钮 | 〈决策·busy-gate〉只认壳 |
| 操作风险 | 覆盖安装丢 origin | 〈决策·migrate-single〉 |
| 演进 | TTS 落地后仍能切站跑朗读 | busy 做成可并入口径，不把判断写死在设置页私有逻辑 |

## 4. 实施计划

### 4.1 子任务拆解

| # | 任务 | 涉及文件/模块 | 验收标准 | 优先级 |
|---|------|---------------|----------|--------|
| 1 | 列表存储 + 旧值迁移 + 去重规范化 | `AppSettings` | 按〈决策·url-only〉〈决策·migrate-single〉 | 必须 |
| 2 | `RunWatchService.isBusy()`（或等价） | `run/RunWatchService` | 按〈决策·busy-gate〉 | 必须 |
| 3 | 切站清 WebView 历史 | `MainActivity` | 按〈决策·clear-history〉 | 必须 |
| 4 | 设置页列表 UI | `SettingsActivity`、layout、strings | 按〈决策·settings-only〉〈决策·keep-one〉 | 必须 |
| 5 | AGENTS.md 能力表一行 | 仓库根 | 能从总览点到本文 | 应该 |

### 4.2 测试要点

- [ ] 添加约 3 个合法 http(s) LAN 地址；点选后主界面为该站。
- [ ] 非法 URL、`127.0.0.1`、与已有项规范化后重复：不能进列表。
- [ ] 有 Run watch 时点选其他项：不切换并提示；停止/结束后可切。
- [ ] A→B 后按返回：不出现 A 站页面。
- [ ] 删除非当前项成功；当前项不可删；不能删到零条。
- [ ] 覆盖安装（或清掉新键只留旧 `server_origin`）：仍打开原 origin 且列表含它。
- [ ] 切回已登录过的站点：无需重登（cookie 按 host 仍在）。
- [ ] 未装壳的桌面浏览器无变化。

### 4.3 首跑策略

## 5. 关键决策与未决项（唯一真相源）

### 5.1 已定决策 / 约束

| 名字 | 结论 | 来源 | 影响位置 |
|------|------|------|----------|
| settings-only | 列表维护与切换只在设置页；主界面仍一块 WebView + 进设置的 FAB | 用户选方案 A | §3、任务#4 |
| url-only | 条目只有规范化 URL，无显示名 | 用户选 A | `AppSettings`、设置行文案 |
| busy-gate | 改当前 origin 前查壳 busy；现 = 仍有 Run watch；TTS 落地后并入同一查询，不读网页 DOM | 用户确认 + 串站重试风险 | 任务#2/#4 |
| clear-history | origin **变更**加载完成后清 WebView 历史；同站刷新不清 | 返回键串站 | 任务#3 |
| keep-one | 禁止删除当前项；列表至少一条，否则回落 `DEFAULT_ORIGIN` | 压力测试 | 任务#4 |
| migrate-single | 读列表时若新键空、旧 `server_origin` 有值，则迁入数组并作为当前 | 覆盖安装 | 任务#1 |
| cap-soft | 按约 3 条做 UI，不做硬上限（多加几条仍是同一列表） | 用户「大概 3」 | 设置页 |
| reuse-webview | 不预热、不并列多 WebView；`loadUrl` 即卸旧站 | 用户确认 | `MainActivity` |
| valid-origin | 仅 `http://` 或 `https://` 开头；拒绝 `127.0.0.1`（含 https） | 现 `isValidOrigin` | 添加/迁移 |
