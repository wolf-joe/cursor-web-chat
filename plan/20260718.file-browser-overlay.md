# 工作区文件浏览 Overlay（`@` 路径引用）

> **文档定位**：**活 spec**（会随实施反复更新）。
> 「关键决策与未决项」表是唯一真相源；正文引用它、不复述它。

## 0. 一页纸（骨架先行）

- **一句话**：在 model-bar 右侧增加「浏览文件夹」入口，用近全宽 Overlay 懒加载浏览当前 cwd 文件树、只读预览常见文本，并把 `@绝对路径` 纯文本插进输入框光标处，让模型更稳地读到指定文件。
- **承重决策**（3~5 条）：
  1. **独立 Overlay + list/read 双 API（方案 A）** —— 与 diff Overlay 平行解耦，避免 mode 切换缠状态机（详见 §3 / 〈决策·independent-overlay〉）。
  2. **`@` 纯文本、不碰 SDK** —— 插入结果只是 composer 字符串，原样进 `/api/chat`；SDK 无文件引用能力（详见 〈决策·plain-at-path〉）。
  3. **懒加载树 + 点文件才读** —— 大仓库不一次拉整树；预览截断服务端强制，对齐 diff（详见 〈决策·lazy-tree〉〈决策·truncation〉）。
  4. **与 diff 互斥；盖 UI 不断 SSE** —— 同时只开一个 Overlay；打开/关闭不 `detachStream`（详见 〈决策·overlay-mutex〉〈决策·keep-stream〉）。
  5. **cwd 白名单 + 路径落在 cwd 内** —— 复用 `assertAllowedCwd`，并用 realpath 防 `..`/symlink 逃逸（详见 〈决策·cwd-allowlist〉〈决策·path-confine〉）。
- **验收总目标**：选中文件夹且非 streaming 时可浏览并插入一个或多个 `@绝对路径`；文本可预览（高亮 / MD 渲染）；二进制与超限有明确跳过原因；安全边界与 SSE 生命周期不被破坏。

> 读者读完这一节，应已掌握「做什么、凭什么这么定、怎么算成功」。后面是证据与落地步骤。

## 1. 需求背景

### 1.1 原始需求

> 在页面底部的输入框附近，准确的说是在那个模型输入那一栏的右侧，我想新增一个浏览文件夹的功能，点开之后可以在弹窗里看到树形的文件列表，可以将某个文件的路径加上艾特前缀加入到输入框里，方便引用文件。也可以预览一些常见的文件，比如说 Python、JavaScript、TypeScript、Markdown 之类的。

后续确认：动机是让模型更稳读到指定文件；只插纯文本 `@`+绝对路径；光标处插入、可多次；只扫当前选中文件夹；不展示点开头项；常见文本只读预览（要语法高亮与 Markdown 渲染效果），图片/二进制不可预览；UI 用 diff 那种近全宽 Overlay；未选文件夹时按钮禁用；后端要 API；SDK 不支持结构化附件。Phase 2/3 再定：树懒加载；预览截断对齐 diff；streaming 时禁用浏览；与 diff Overlay 互斥；选定独立 Overlay + 双 API（方案 A）。

### 1.2 背景与动机

Local agent 直接读写磁盘，但聊天输入只能靠用户手打路径。把「看见文件 → 确认内容 → 把路径写进 prompt」收在同一 Overlay，降低漏路径/错路径，让模型更容易主动去读对文件。

### 1.3 目标与验收标准

- model-bar 右侧有浏览入口；无 cwd / streaming 时禁用。
- Overlay：左懒加载树、右只读预览；无点开头目录/文件。
- 常见文本可预览（代码高亮；Markdown 渲染）；不可预览有原因（〈决策·truncation〉）。
- 光标处插入 `@`+绝对路径；插完关 Overlay，再开可继续插；发送仍为普通文本（〈决策·plain-at-path〉〈决策·close-on-insert〉）。
- MD 预览样式与 AI 消息卡片一致（〈决策·md-preview-msg-text〉）。
- 与 diff 互斥；打开期间 SSE 不停（〈决策·overlay-mutex〉〈决策·keep-stream〉）。
- 白名单外 cwd、逃逸路径被拒绝（〈决策·cwd-allowlist〉〈决策·path-confine〉）。

### 1.4 约束与前提

- 前端仍是无构建单页、无前端 npm；高亮 CDN 与主题已钉死（〈决策·highlight-cdn〉），MD 复用已有 `marked`。
- 能力落在 `public/` + Express API；不改 agent/run/SSE 协议。
- 易变阈值（预览行数上限、单目录条目上限）收口 §5，正文不复述多份。

## 2. 现状分析

### 2.1 相关代码/系统现状

- **入口空位**：`public/index.html` 的 `.model-bar` 仅有模型下拉、参数按钮与摘要；`setComposerEnabled` 在无 cwd / streaming 时禁用 composer 与模型控件，浏览按钮需同节奏接入。
- **Overlay 先例**：`public/gitDiff.js` + diff Overlay——近全宽、左列表右内容、Esc、seq 防过期、`onCwdChangedForDiff`、打开不 `detachStream`。本需求平行新建壳与模块，不复用 diff 的 mode 切换。
- **安全先例**：`server.ts` 的 `assertAllowedCwd`（`决策·cwd-allowlist`）已被 git 读/写 API 共用；尚无通用「列目录 / 读文件」API，也无路径禁锢辅助。
- **渲染**：聊天气泡已用 CDN `marked`；仓库无语法高亮库。
- **composer**：原生 `<textarea>`；无光标插入封装；发送走 `postChat` 纯文本。

### 2.3 现状与目标的差距

| 目标 | 现状 | Gap |
|------|------|-----|
| 浏览当前 cwd 文件树 | 无 | list API + 懒加载树 UI |
| 预览文本 / 跳过非文本 | 无 | read API + 截断/skipped + 右栏渲染 |
| 光标插入 `@绝对路径` | 无 | textarea selection 插入 + autoGrow |
| 与 diff 互斥、不断 SSE | 仅 diff 自管 | 互关接线 + 不碰 detachStream |
| 路径不逃逸出 cwd | 仅 cwd 字符串白名单 | realpath + 前缀校验 |

### 2.4 影响范围

- **会改**：`src/server.ts`；新建 fs 列目录/读文件模块；`public/index.html`、`style.css`、`api.js`、`dom.js`、`render.js`（enabled）、`app.js`（cwd 切换钩子）；新建 `public/fileBrowser.js`（名可调）；diff 侧增加「打开时关掉文件浏览」的互斥调用（尽量薄）。
- **基本不动**：`agentService` / `runHub` / `history` / 发消息与 SSE 契约；`composer.js` 发送逻辑（最多导出或复用 `autoGrowComposer`）。
- **文档**：本文件；实施时在 diff Overlay 活 spec 决策表可加一行「与 file-browser 互斥」指向本文，避免两处各写一套互斥规则。

## 3. 方案设计

### 方案 A：独立 Overlay + list/read 双 API（选定 / 推荐）

- **思路**：model-bar 右侧按钮 → 打开独立近全宽 Overlay。左：懒加载树（点目录再 `list`）；右：点文件再 `read` 预览。动作：把服务端返回的绝对路径以 `@path` 插到 composer 光标处。打开本 Overlay 时关闭 diff，反之亦然。
- **改动范围**：见 §2.4。
- **优点**：与 diff 解耦、回归面小；API 职责清晰；契合懒加载与截断。
- **缺点/风险**：多一套 Overlay DOM/CSS；互斥需显式接线（已纳入 〈决策·overlay-mutex〉）。
- **工作量**：M

### 方案 B：复用 diff Overlay 壳，mode 切换（未选）

同一 DOM、`mode=diff|browse`。前期少一套壳，但 diff 与浏览状态机、顶栏动作缠在一起，回归风险高。

### 方案 C：一次拉整树（未选）

与已定懒加载冲突；大仓库首开易卡。

### 方案对比

| 维度 | A 独立 Overlay | B 复用 diff 壳 | C 整树 |
|------|----------------|----------------|--------|
| 回归风险 | 低 | 中高 | 高（规模） |
| 懒加载契合 | 好 | 可做 | 冲突 |
| 互斥 | 显式互关 | 天然单实例 | — |
| 工作量 | M | M | 表面 S |

### 最终选定

**方案 A**，用户 Phase 3 明确选定：独立 Overlay、双 API、与 diff 解耦。

### 执行步骤

原则：**先安全契约与截断，再 Overlay 壳，再树/预览，最后插入与按钮联动；全程不碰 stream。**

1. **后端 list / read** —— 白名单 cwd（〈决策·cwd-allowlist〉）；子路径经 realpath 后必须落在 cwd 内（〈决策·path-confine〉）；`list` 只返回非点开头子项，含类型与绝对路径；`read` 返回文本或 `skipped`（binary / too_large），截断阈值按 〈决策·truncation〉 服务端强制。
2. **独立 Overlay 壳** —— 近全宽面板（不要复用 380px 参数 modal）；顶栏文件夹名与关闭即可，**不做刷新按钮**（关后再开即整树重拉，〈决策·refresh-ux〉）；Esc / 遮罩关闭；打开时关 diff，diff 打开时关本 Overlay（〈决策·overlay-mutex〉〈决策·overlay-shell〉）。
3. **懒加载树 + 预览** —— 根为当前 cwd；点目录再请求 list；点文件再 read；MD 用已有 `marked`；代码用钉死的 highlight.js CDN（〈决策·highlight-cdn〉）；skipped / 错误右栏明示。
4. **插入 `@绝对路径`** —— 使用 textarea `selectionStart`/`selectionEnd` 在光标处插入；片段为 ` @绝对路径 `（前后各一空格，〈决策·insert-spacing〉）；插入成功后关闭 Overlay（〈决策·close-on-insert〉）；再开可继续插；不改 `/api/chat` 与 SDK（〈决策·plain-at-path〉）。MD 预览挂 `.msg-text`（〈决策·md-preview-msg-text〉）。
5. **按钮与 enabled 联动** —— model-bar 右侧；无 cwd 时禁用；streaming 中仍可打开只读浏览（〈决策·browse-enabled〉；插入 @路径仍受 composer disabled 限制）。
6. **会话切换与过期请求** —— 切 cwd 时关闭或按新 cwd 重开根；请求 seq/cwd 校验丢弃过期响应（对齐 diff）。
7. **回归确认** —— 打开路径不调用 `detachStream`（〈决策·keep-stream〉）；diff 与浏览互斥。

### 压力测试

| 压力维度 | 具体场景 | 方案表现 | 是否需要防御性设计 |
|----------|---------|----------|------------------|
| 故障容错 | `..` / symlink 逃出 cwd | 拒绝并错误态 | 是：〈决策·path-confine〉 |
| 规模压力 | 单目录海量条目 / 超大文件 | 不加限会拖垮 Node/浏览器 | 是：〈决策·truncation〉〈决策·list-cap〉 |
| 操作风险 | 两 Overlay 同开、切 cwd 串数据 | 错数据或 Esc 混乱 | 是：互斥 + seq/cwd |
| 与对话并存 | Overlay 开着 SSE 仍在推 | 若误 detach 丢直播 | 是：〈决策·keep-stream〉 |
